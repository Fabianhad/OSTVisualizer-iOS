# OST Visualizer - iOS Porting Map

Last updated: 2026-11-15

Desktop module to iOS module map. Rewritten from the code: every path below was checked to exist (iOS working tree at HEAD `4a1302d` plus the uncommitted Phase 0 files; Windows repo `OSTVisualizerLicense` at HEAD `dceb47d`). Parity ids come from `PARITY_MAP.md` (216 divergences from Phase 1); that file holds the evidence, the Windows tests and the decision questions for each id. Current status per area is in `PORTING_STATUS.md`, remaining work in `PORTING_PLAN.md`.

## How to read this map

| Status | Meaning |
|---|---|
| Implemented-matches-Windows | Compared with the Windows code (diff of the vendored C++, or a Phase 1 differential run) and equal for what was compared |
| Implemented-diverges | Implemented, and at least one parity id differs from Windows (ids in the next column) |
| Implemented-unverified | Present but not compared or run here (build files, test harness, Nyxian config) |
| Replaced (platform) | Different technology by design (UIKit for Qt, bgfx/Metal for OpenGL, CoreGraphics for PDFium, SQLite for Access); the ids are behaviour differences that remain |
| Not implemented | Windows has it, iOS does not, or iOS only models the fields and never uses them |
| Obsolete | Tied to the Windows desktop; no iOS counterpart planned |

Parity ids: `(d)` = needs-decision (`PARITY_MAP.md` section E), `(c)` = cannot-reproduce (section F), no suffix = `fix`. `-` = none. An id is listed in each row whose iOS files take part in it, so an id can appear in several rows. All 216 ids appear at least once.

Rows by status (109 rows): Implemented-matches-Windows 14; Implemented-diverges 44; Implemented-unverified 4; Replaced (platform) 13; Not implemented 27; Obsolete 7.

## Evidence and limits

- Paths: every iOS and Windows path in the tables was checked with a script against the two working trees (not committed). Directories are cited where a whole folder is meant.
- "Matches" rests on `diff` of the vendored C++ modules (only include lines differ unless stated) and on the Phase 1 differential runs, where the real iOS C++ sources were compiled on the host with MSVC and compared with the Windows Python and native modules.
- Objective-C, Objective-C++ and UIKit code (`Controllers/`, `PlanView/`, `Services/`, `Rendering/`, `SceneDelegate.mm`) was read, not compiled or run. Nothing was built or run on iOS in this job (no Xcode, macOS or device). Rendering, PDF drawing, share sheets and the CI build are therefore not verified.
