# OST Visualizer - iOS Porting Map

Last updated: 2026-11-19

Desktop module to iOS module map, rewritten from the code after the parity job: every path below was checked to exist (iOS working tree on branch `ios-parity-sync` at HEAD `42b46c3` plus the uncommitted work of the job; Windows repo `OSTVisualizerLicense` at HEAD `6d4786f`, read only). Parity ids come from `PARITY_MAP.md` (220 items: the 216 divergences of Phase 1 plus RB-01 to RB-04); that file holds the evidence, the Windows tests and the decision questions for each id, `PARITY_DIVERGENCES.json` (repository root) holds the item records. The mark after an id is its final status. The decisions of 2026-11-19, what is still open and what cannot be verified here are in `PORTING_BLOCKERS.md`, current status per area in `PORTING_STATUS.md`, history in `PORTING_PLAN.md`.

The job moved the platform-independent logic out of the Objective-C++ files into `Core/` (new headers and sources in `Core/Data`, `Core/Domain`, `Core/Export`, `Core/Geometry`, `Core/Import`, `Core/Meshing` and `Core/Persistence`), ported it from the Windows source with host tests, and wired the platform layer to it. Section 13 lists which platform file calls which Core module, section 14 the test areas.

## How to read this map

| Status | Meaning |
|---|---|
| Implemented-matches-Windows | Every parity id of the row is fixed (or no longer divergent): the Core logic was ported from the Windows source and is pinned by host tests with Windows data, or the vendored C++ is identical to Windows (diff). Ids marked (u) have platform parts (UIKit, CoreGraphics) that were only syntax-checked. |
| Implemented-diverges | Implemented, and at least one id of the row is a deliberate or unavoidable difference: (w) closed by a user decision, (c) cannot be reproduced on iOS. |
| Implemented-unverified | Present but never run: build files, CI, the test harness on CI, Nyxian config |
| Replaced (platform) | Different technology by design (UIKit for Qt, bgfx/Metal for OpenGL, CoreGraphics for PDFium, SQLite for Access); the ids are behaviour differences that were fixed or remain |
| Not implemented | Windows has it, iOS does not (no new features were added by the job) |
| Obsolete | Tied to the Windows desktop; no iOS counterpart needed |

Marks after a parity id: none = fixed (Core logic host-tested, platform call wired); `(u)` = fixed, but UIKit/CoreGraphics parts only syntax-checked, needs a device (25 ids, table in `PORTING_BLOCKERS.md`); `(w)` = closed by a user decision, iOS behaviour kept (21 ids: 13 of 2026-11-16 and the 8 former open decisions DBP-04, BRW-09, EXP-12, EXP-13, EXP-16, IMP-20, LP-24 and RPV-29 of 2026-11-19); `(c)` = cannot be reproduced on iOS (EXP-24); `(n)` = no longer divergent (MSH-19); `(k)` = fixed, and a difference to Windows was kept by a decision of 2026-11-19, no code change (11 ids: COND-UPD-02, COND-FOLDER-01, DBP-33, EXP-21, EXP-09, RPV-26, RPV-27, RPV-16, UND-02, GEO-M02, IMP-12); `(x)` = fixed, with a deliberate deviation from the literal Windows behaviour decided on 2026-11-19 (COND-STYLE-02, COND-ELEV-01); `(q)` added = fixed, with a smaller question still open (DLG-FINITE-01: condition number; COND-PLACE-01: two notes; section "Still open" in `PORTING_BLOCKERS.md`). `-` = none. ## Evidence and limits

- Paths: every iOS and Windows path in the tables was checked with a script against the two working trees on 2026-11-18 (nothing was written to the Windows tree). Directories are cited where a whole folder is meant.
- 'Matches' rests on `diff` of the vendored C++ modules (only include lines differ unless stated), on the Phase 1 differential runs (marked as such), and on the host tests of this job: `Config/Tests` holds 1598 tests (1606 with Manifold) that compare the Core with Windows data (oracle tables and fixtures produced by running the Windows implementation, and ports of Windows tests). They run on MSVC and on a clang build with fused multiply-add; the CI run on macOS has not happened for this code.
- Objective-C, Objective-C++ and UIKit code (`Controllers/`, `PlanView/`, `Services/`, `Rendering/*.mm`, `SceneDelegate.mm`) was changed to call the Core and was syntax-checked with clang against hand-written stub headers (27 of 27 files, 0 errors, 4 baseline warnings). That finds typos, wrong Core call signatures and missing includes; it does not check against the real Apple SDK and runs nothing. Nothing was built, signed, installed or run on iOS or macOS in this job (no Xcode, XcodeGen, ldid, macOS or device). Rendering, PDF drawing, share sheets and the CI build are therefore not verified.
