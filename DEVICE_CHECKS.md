**How to use it**
1. Import every file of `DeviceTestPack/` first (AirDrop, or Files > tap the file > Open in OST Visualizer, or the Import button of the Projects screen, one file at a time). Each file is one bid and shows up unfiled (under `Unassigned Projects`) as `M1-0x ...`. `DeviceTestPack/README.md` says what each file holds.
2. Do the rows. In the Result column write **Pass**, **Fail** (and what you saw) or **Not run** (and why). A crash, a freeze, or a text that differs from the quoted one is a Fail.
3. Send the table back.

Rows that write to a bid change it. Import the file again when a row needs the original names or content (each import is a separate copy with the same name: move the used copy to Deleted Bids first).

The expected results come from the code and the Windows rules. Nothing below has been seen running on a device yet.

**Words used**
- Bottom toolbar: `Reset` (3D only), `Undo`, `Redo`, `Delete` (these three 2D only), `Conds`, `Layers`, `Export`. `Conds` opens the Conditions sheet, `Layers` the Layers sheet. Both open full height; drag the grabber down to half height and the plan stays usable.
- Page bars: two scrolling rows of page buttons (3D and 2D), each starting with a `3D` or `2D` chip. Tap the chip to change mode. The active chip is blue (3D) or green (2D), the other dim grey. The app can open in 3D: tap `2D` before any row that selects, places, zooms or reads the Place mode.
- Long-press: touch and hold about half a second. Floating mode button: the round button that shows View, Select or Place in 2D (Orbit or Pan in 3D); tap it to open the ring of modes.
- `Title` / `Message` is an alert with that title and text. `(i)` is the round info button at the right of a condition row.
- Pack bids have no condition types, so every condition sits in a group headed `(unassigned)`; a folder's group is headed `Folder > Sub-folder — (unassigned)`; an empty folder is a heading with no rows. iOS may draw headings in capitals.

# Known behaviour, not a failure

- After you tap a page button the `2D` and `3D` chips can show the dim colour (existing behaviour; a page rename or a page delete repaints them, a page tap does not).
- The Rise and Run keypad has no minus key, and with a comma-decimal language `.` cannot be typed there (existing behaviour).
- A refused New Layer name closes the alert: tap `+` and type again. Windows keeps the typed text. Decision pending.
- A bid whose job status is Locked refuses every M1 write with `Bid Locked` / `This bid is locked.` Opening the `Folders` screen is allowed; the actions in it are refused. The same alert appears if the status list cannot be read. Existing edits (editing a condition, placing takeoffs) are not blocked.
- Set Scale on a page with no stored scale opens as 1:1 and every Save answers `Save Failed` / `Failed to save page scale.` No pack bid has such a page.
- The scale text drawn inside the pack PDFs does not change with Set Scale.
- New Condition, folders, layers and rename have no Undo. Delete Page empties the Undo history. Set Scale keeps it.
- The 3D page bar menu has `Rename Page...` only. Set Scale and Delete Page are on the 2D bar.
- A page name with spaces at its ends is saved without them after a rename.
- Folders cannot be moved or dragged; `Move to Folder...` moves one condition.
- Set Scale and Delete Page run on the main thread; a very large bid can pause for a moment (see M1-17a).
